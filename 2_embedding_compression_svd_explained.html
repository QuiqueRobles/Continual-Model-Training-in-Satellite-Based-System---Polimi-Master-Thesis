Step 2

Embedding Extraction and SVD Compression

Core part of the TFM — Simulating satellite onboard processing with embeddings

🎯 Objective of This Script

This script is the technical core of the project. It simulates a complete satellite-to-ground intelligent compression pipeline:

Satellite side (onboard):
Raw Sentinel-2 image → Frozen UNet backbone → Extract embedding + skip connections → Compress embedding with SVD → Downlink compressed data

Ground side:
Receive compressed embedding → Reconstruct full prediction using the decoder

The goal is to dramatically reduce the amount of data transmitted from the satellite while maintaining high water detection accuracy (measured by IoU).

🧠 Model Used

We use the same pre-trained UNet model as in previous steps (WF2_unetv2_bgriswirs).

Key idea: We freeze the entire model to simulate the satellite's onboard backbone. Only the encoder (backbone) runs on the satellite. The decoder runs on the ground after receiving the compressed embedding.

🔬 Deep Dive: Model Freezing + Embeddings Extraction

1. What Does “Freezing the Model” Mean?

After loading the pre-trained UNet, we execute this code:

            for param in model.parameters():
                param.requires_grad = False
            model.eval()

Technical effect:

  • requires_grad = False → All weights become read-only (no gradients are computed or stored).
  • model.eval() → Turns off dropout and batch-norm training mode (uses running statistics).

Why we do it: This perfectly simulates a satellite onboard computer. The model weights are fixed once and for all (no training happens in space). The backbone runs in pure inference mode, using almost no extra memory or power.

2. What Are We Extracting? (The Embeddings + Skip Connections)

We register four forward hooks on specific layers of the UNet encoder:

            model.dconv_down1.register_forward_hook(...)  # conv1  → [1, 64, 128, 128]
            model.dconv_down2.register_forward_hook(...)  # conv2  → [1, 128, 64, 64]
            model.dconv_down3.register_forward_hook(...)  # conv3  → [1, 256, 32, 32]
            model.dconv_down4.register_forward_hook(...)  # emb    → [1, 512, 16, 16]  ← bottleneck!

What each tensor represents:

Layer Tensor shape Meaning in UNet Why we keep it
dconv_down1 [1, 64, 128, 128] Early low-level features (edges, textures) Skip connection for fine details
dconv_down2 [1, 128, 64, 64] Mid-level features Skip connection
dconv_down3 [1, 256, 32, 32] High-level semantic features Skip connection
dconv_down4 [1, 512, 16, 16] Deepest embedding / bottleneck Most compressed representation of the entire image
Key insight:
The embedding (emb) is the smallest and most information-dense tensor produced by the encoder. It contains everything the decoder needs to reconstruct the final segmentation. By compressing only this tensor, we achieve massive data reduction while still being able to recover almost the original prediction on the ground.

3. Why Only Compress the Embedding?

On the satellite we only transmit the compressed emb (the 512-channel 16×16 bottleneck).

On the ground we:

  1. Receive the compressed embedding
  2. Re-use the exact same frozen backbone to re-compute the three skip connections (conv1, conv2, conv3) — they are identical because the backbone never changes
  3. Feed emb + the three skips into the decoder (exactly as the original UNet does)

This design gives us the best of both worlds: maximum compression on the satellite side + full decoder quality on the ground.

4. Simple Technical Summary of What Happens

1. Image (6 bands, 256×256) → Frozen encoder → 4 tensors captured
2. Only the deepest embedding [1, 512, 16, 16] is sent through SVD compression
3. Ground receives ~10% of the original embedding size
4. Ground re-computes skips + runs decoder → almost identical water map

This is exactly how future “smart satellites” will work: they extract a compact embedding onboard, compress it, and downlink only what is essential.

compress_svd(tensor, k_ratio=0.1)
            def compress_svd(tensor, k_ratio=0.1):
                arr = tensor.squeeze(0).numpy()          # shape: [C, H, W]   e.g. [512, 16, 16]
                C, H, W = arr.shape
                mat = arr.reshape(C, H*W)                # reshape to matrix [C, H*W]
            
                U, S, Vt = np.linalg.svd(mat, full_matrices=False)
            
                k = max(1, int(len(S) * k_ratio))       # keep only 10% of singular values
                Uk  = U[:, :k]
                Sk  = S[:k]
                Vtk = Vt[:k, :]
            
                recon = (Uk @ np.diag(Sk) @ Vtk).reshape(C, H, W)
            
                bytes_orig = arr.nbytes
                bytes_comp = Uk.nbytes + Sk.nbytes + Vtk.nbytes
                return torch.tensor(recon).unsqueeze(0).float(), bytes_orig, bytes_comp

Step-by-Step: What Happens Inside

  1. Input tensor
    We receive the deep embedding from the frozen encoder: shape [1, 512, 16, 16].
    We remove the batch dimension → [512, 16, 16].
  2. Reshape into a matrix
    We flatten the spatial dimensions: [512, 16×16] = [512, 256].
    Now every row is one channel, and every column is one “pixel” in the flattened 16×16 feature map.
  3. Compute Singular Value Decomposition (SVD)
    np.linalg.svd(mat, full_matrices=False) gives us three matrices:
    U [512 × 256]  S [256] (singular values, sorted descending)  Vt [256 × 256]

    Mathematically the decomposition is exact:
    mat = U ⋅ diag(S) ⋅ Vt
  4. Truncation (the compression step)
    We keep only the first k = 10% of singular values.
    Example: original has 256 singular values → we keep only the top 26 (k_ratio=0.1).
    We discard the rest → this removes the least important information while keeping the most dominant patterns.
  5. Reconstruction
    We build the low-rank approximation:
    reconstructed = U[:,:k] ⋅ diag(S[:k]) ⋅ Vt[:k,:]
    Then reshape back to the original spatial shape [512, 16, 16].
  6. Memory calculation
    We compare the number of bytes before and after:
    Original = 512 × 16 × 16 × 4 bytes (float32)
    Compressed = bytes of Uk + Sk + Vtk
    The function returns both the reconstructed tensor and the exact byte counts.
Why SVD is perfect for this task
• It is a mathematically optimal low-rank approximation (best possible compression for a given number of components).
• It works extremely well on feature maps from neural networks because they usually have a lot of redundancy.
• It is linear and very fast to compute (no training needed).
• On a satellite, you could even run a fast approximated SVD or use hardware-accelerated versions.

Visual Intuition of the Compression

Think of the embedding matrix [512 × 256] as a photo that can be compressed by keeping only the 10% most important “colors” (singular vectors). The reconstructed version looks almost identical to the human eye (and to the decoder), but uses ~90% fewer numbers.

Bottom line: With k_ratio=0.1 we typically reduce the embedding size by 85–92% while losing only a tiny fraction of the final water IoU. This is exactly the trade-off we want for a real satellite downlink.

decoder_from_features(model, emb, conv1, conv2, conv3)
            def decoder_from_features(model, emb, conv1, conv2, conv3):
                x = F.interpolate(emb, scale_factor=2, mode='bilinear', align_corners=True)
                x = torch.cat([x, conv3], dim=1)
                x = model.dconv_up3(x)
            
                x = F.interpolate(x, scale_factor=2, mode='bilinear', align_corners=True)
                x = torch.cat([x, conv2], dim=1)
                x = model.dconv_up2(x)
            
                x = F.interpolate(x, scale_factor=2, mode='bilinear', align_corners=True)
                x = torch.cat([x, conv1], dim=1)
                x = model.dconv_up1(x)
            
                return model.conv_last(x)

Important Clarification First

This function does NOT retrain the model.
There is zero training happening here. The entire model (backbone + decoder) was already trained and is now frozen. This function only runs inference on the ground using the embedding sent from the satellite.

What This Function Actually Does

It manually reproduces the decoder part of the original UNet, exactly as the full model would do after the encoder finishes.

In the satellite-ground pipeline we simulate:

  • Satellite → runs the frozen encoder → extracts the deep embedding (emb) → compresses it with SVD → downlinks only the compressed embedding.
  • Ground → receives the compressed emb → runs this decoder_from_features function to reconstruct the final segmentation map.

Step-by-Step Execution (with tensor shapes)

  1. Start with the received embedding
    Input emb shape: [1, 512, 16, 16] (the bottleneck feature map from dconv_down4).
  2. First upsampling + skip connection
    F.interpolate(emb, scale_factor=2) → becomes [1, 512, 32, 32]
    Concatenate with conv3 ([1, 256, 32, 32]) → [1, 768, 32, 32]
    Pass through model.dconv_up3 (a double-conv block) → [1, 256, 32, 32]
  3. Second upsampling + skip connection
    Upsample → [1, 256, 64, 64]
    Concatenate with conv2 ([1, 128, 64, 64]) → [1, 384, 64, 64]
    Pass through model.dconv_up2 → [1, 128, 64, 64]
  4. Third upsampling + skip connection
    Upsample → [1, 128, 128, 128]
    Concatenate with conv1 ([1, 64, 128, 128]) → [1, 192, 128, 128]
    Pass through model.dconv_up1 → [1, 64, 128, 128]
  5. Final classification layer
    model.conv_last(x) → outputs [1, 2, 256, 256] (raw logits for cloud and water).
Why the skip connections (conv1, conv2, conv3) are needed
The decoder uses these “shortcut” features from the encoder to recover fine spatial details (edges of rivers, small flooded areas). Without them the output would be blurry. By sending only the embedding from the satellite and re-using the same frozen backbone on the ground, we can recompute the exact same skip connections locally — no extra data needs to be transmitted.

How This Simulates the Real Satellite-to-Ground Pipeline

In a real mission:

  • Satellite only needs to run the encoder (frozen) + SVD compression → very low power and memory.
  • Only the small compressed embedding is downlinked (typically 85–92% smaller than the original image).
  • Ground station runs only the decoder (this function) using the received embedding + locally recomputed skips.
  • Result: almost identical water map as if the full model had run on the satellite, but with dramatically less data transmitted.

Summary: decoder_from_features is the ground-side reconstruction step. It takes the compressed embedding sent by the satellite and turns it back into a full-resolution flood map by replaying exactly the same decoder operations the original UNet would have used — no retraining involved.

🔄 Overall Workflow

  1. Load and freeze the UNet model (simulating satellite hardware)
  2. Register hooks to capture intermediate features (embedding + skips)
  3. For each test image:
    • Preprocess and select best tile
    • Run full forward pass to get original prediction and capture features
    • Compress only the deep embedding using SVD
    • Reconstruct prediction on "ground" using decoder_from_features()
    • Compare IoU and calculate compression ratio
  4. Generate summary statistics and two comparison plots

📊 What We Measure

  • Compression ratio: How much smaller the transmitted embedding is compared to the original 6-band image
  • IoU degradation: Difference in water detection accuracy between the full model and the compressed version
  • Trade-off: We aim for maximum data reduction with minimal loss in segmentation quality

The plots show both the IoU comparison per image and the average size reduction achieved.
