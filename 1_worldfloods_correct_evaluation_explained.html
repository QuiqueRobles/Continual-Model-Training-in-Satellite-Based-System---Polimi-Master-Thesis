WorldFloods v2

Flood Detection Model Evaluation Script

This is the main evaluation script that measures how well our neural network detects water from Sentinel-2 satellite images.

🎯 What is the Goal of This Script?

The purpose of this script is to evaluate a deep learning model designed to detect floods (specifically water bodies) in Sentinel-2 satellite imagery.

It processes test images from the WorldFloods v2 dataset, runs the model on selected tiles, compares the predictions against the official ground truth, and calculates the Intersection over Union (IoU) for the water class. Finally, it generates a visual report with RGB images, ground truth, and model predictions.

🧠 The Model We Are Using

Model Name: WF2_unetv2_bgriswirs (UNet variant trained on WorldFloods v2)

Architecture: UNet (Encoder-Decoder with skip connections)

Why UNet?
UNet is one of the most popular architectures for semantic segmentation tasks, especially in medical imaging and remote sensing. It consists of a contracting path (encoder) that captures context and a symmetric expanding path (decoder) that enables precise localization. Skip connections between encoder and decoder help preserve fine spatial details — very important when detecting thin rivers or small flooded areas.

Key Technical Specifications

  • Input Channels: 6 spectral bands from Sentinel-2 satellite
  • Output Channels: 2 independent heads (multi-output design)
  • Input Tile Size: 256 × 256 pixels
  • Output Resolution: Same as input (256 × 256)
  • Framework: PyTorch + custom ml4floods UNet implementation

Input Bands (bgriswirs configuration)

The model was trained using 6 carefully selected Sentinel-2 bands:

Band Name Wavelength Why it helps
B2 Blue ~490 nm Good for water penetration
B3 Green ~560 nm Vegetation and water contrast
B4 Red ~665 nm Strong water absorption
B8 NIR (Near Infrared) ~842 nm Excellent for land-water separation
B11 SWIR 1 ~1610 nm Sensitive to moisture content
B12 SWIR 2 ~2190 nm Strong cloud and water discrimination

Output Design – Why 2 Channels?

The model produces two independent probability maps instead of a single multi-class output:

  • Channel 0: Cloud probability (sigmoid applied)
  • Channel 1: Water probability (sigmoid applied)

Advantages of this multi-output approach:

  • Allows the model to detect clouds and water simultaneously (a pixel can theoretically have high probability for both)
  • Clouds can be flagged even if water is also predicted underneath (important for cloudy flood scenes)
  • During post-processing, we give priority to clouds: if cloud prob > 0.5, the pixel becomes class 2 (cloud), even if water probability is also high.

Training & Preprocessing Details

  • Normalization: The 6 bands are normalized using dataset-specific mean and standard deviation values (get_normalisation("bgriswirs")). This is crucial because Sentinel-2 reflectance values have very different ranges.
  • Pre-trained weights: Loaded from Hugging Face repository isp-uv-es/ml4floods → file models/WF2_unetv2_bgriswirs/model.pt
  • Model state dict cleaning: The code removes the "network." prefix from the saved weights to match the current UNet architecture.
  • Evaluation mode: model.eval() is called so that batch normalization and dropout layers behave correctly during inference.

Post-processing in Inference

After the model runs:

  1. Raw logits → Sigmoid → probabilities between 0 and 1 for each channel
  2. Start with all pixels as class 0 (Land)
  3. If water probability > 0.5 → assign class 1 (Water)
  4. If cloud probability > 0.5 → assign class 2 (Cloud) (overrides water if both are true)

This results in a clean 256×256 integer map ready for IoU calculation and visualization.

Note: The model was specifically trained on the WorldFloods v2 dataset using the "bgriswirs" band combination, which explains why we select exactly those 6 bands and apply the matching normalization.

🔧 Functions in the Code

🔍 find_best_tile(image_norm, gt_water)

What it does:

Scans a large Sentinel-2 image and selects the best 256×256 tile for evaluation.

It prefers tiles that:

  • Have at least 30% valid ground-truth pixels
  • Contain a reasonable amount of water (> 5%)
  • Have high variance (rich visual information)

Returns the normalized image tile, the corresponding water ground truth, and its position in the original image.

🧠 inference_multioutput(model, tile_img)

What it does:

This is the core inference function. It takes a normalized 256×256×6 tile and runs it through the UNet model to produce a pixel-wise prediction map with three possible classes: Land (0), Water (1), or Cloud (2).

Step-by-step breakdown of the inference process:
  1. Tensor preparation
    The input tile_img (a NumPy array of shape [6, 256, 256]) is converted into a PyTorch tensor and a batch dimension is added with .unsqueeze(0), resulting in shape [1, 6, 256, 256].
  2. Forward pass with torch.no_grad()
    The model is executed inside a with torch.no_grad(): context. This disables gradient tracking, which makes inference faster and uses less memory (no need to store computation graphs).
  3. Model output (logits)
    The UNet returns raw logits of shape [1, 2, 256, 256]:
    • Channel 0 = raw scores for clouds
    • Channel 1 = raw scores for water
    These values can be any real number (positive or negative).
  4. Sigmoid activation
    torch.sigmoid(logits) is applied independently to each channel. This converts the raw logits into probabilities between 0 and 1 for each class separately. Because the model was trained with two independent output heads, both a pixel can have high probability for water and cloud at the same time.
  5. Creating the final class map
    A zero-initialized integer array (np.zeros(..., dtype=np.int32)) is created — this defaults every pixel to class 0 (Land).

    Then two masking operations are performed in order: 
    prediction_map[probs[1] > 0.5] = 1   # Water (if water probability > 50%)
prediction_map[probs[0] > 0.5] = 2   # Cloud (if cloud probability > 50%)
    Important: The cloud assignment happens after water. This means if a pixel has high probability for both water and cloud, it will be classified as Cloud (2) — cloud takes priority in this implementation.
  6. Final output
    A clean 256×256 integer array where each pixel is exactly 0, 1, or 2.

Why this design?

  • Using two separate sigmoid outputs allows the model to detect clouds and water independently (multi-label style).
  • Thresholding at exactly 0.5 is a standard and simple decision boundary for binary classification per channel.
  • The function is kept very lightweight so it can be called thousands of times during evaluation without slowing down.
📏 calculate_water_iou(prediction_map, gt_water_channel)

What it does:

Calculates the Intersection over Union (IoU) specifically for the water class.

It only considers:

  • Valid pixels in the ground truth (value ≠ 0)
  • Pixels that the model did not classify as clouds

This gives a reliable metric of how well the model detects water.

🎨 apply_colors(map_array, color_table)

What it does:

Converts a class map (with values 0, 1, 2) into an RGB image for visualization.

Used to display both the ground truth water mask and the model’s prediction in nice colors.

🔄 Overall Workflow

  1. Setup & Loading
    Download and inspect a sample ground-truth image to understand its 2-channel structure (clouds in band 1, water in band 2).
    Load the pre-trained UNet model and prepare normalization parameters.

  2. Process Test Images
    Loop through all Sentinel-2 images in the test folder of the WorldFloods v2 dataset.

  3. For each image:
    • Load the Sentinel-2 image (6 selected bands) and its corresponding 2-channel ground truth
    • Normalize the image using dataset-specific mean and std
    • Find the best 256×256 tile using find_best_tile()
    • Run model inference using inference_multioutput()
    • Calculate Water IoU using calculate_water_iou()
    • Store results and save selected tiles for visualization

  4. Generate Report
    Print a summary table with % water in GT, % clouds predicted, and IoU for each image.
    Show global statistics (mean, median, min, and max IoU).
    Create a multi-panel visualization plot and save it as correct_evaluation.png.

📊 Final Output

When you run this script, you will obtain:
  • A clear table in the console showing performance per image
  • Overall statistics of the model’s water detection capability
  • A visual report (PNG file) displaying Sentinel-2 RGB, Ground Truth water mask, and Model Prediction side by side
